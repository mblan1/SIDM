Snw Internet Download Manager

Fast multi-segment downloads, browser capture, native HLS & DASH video grabbing, queue + schedule + bandwidth governor — for modern Windows.

⬇ Download for Windows View source

Windows 10 / 11 · 64-bit · ~70 MB · Open source · MIT · Auto-updates via Velopack

What you get

Real multi-segment

1–16 parallel range requests per download, sparse-file writes, single-stream fallback when servers fib about Accept-Ranges. Resumes across app restarts.

Browser capture

Chrome MV3 and Firefox MV3 extensions intercept downloads with full cookies / referer / User-Agent replay, so SIDM gets the exact bytes the browser would have.

HLS & DASH from scratch

Pure-C# m3u8 parser with AES-128 decrypt and pure-C# MPD parser with video + audio mux via ffmpeg. yt-dlp routing for YouTube & friends.

Queue & bandwidth

Cap concurrent downloads, set a global token-bucket speed limit, define time-window schedule rules with their own per-window overrides. Drop 50 URLs and walk away.

One-click capture popup

SIDM extension auto-sniffs HLS / DASH manifests on every page. The toolbar badge shows the count; the popup lets you grab any of them with one click.

Auto-updates

Velopack delta updates from a single configurable feed URL. Toggleable in Settings. Signed installer, opt-in crash reports with URL / cookie / filename scrubbing.

Privacy

SIDM is open source under MIT. The desktop app and browser extensions process data on your machine only. We do not run a server, do not collect analytics, and do not transmit anything except the download URLs you explicitly ask SIDM to fetch.

Browser extension permissions

  • downloads — to intercept the file the browser is about to save and redirect it to SIDM.
  • cookies + <all_urls> — to forward the same authentication cookies the browser would have used, so SIDM can fetch the exact bytes (gated downloads, signed URLs, etc.). The extension reads cookies only for the host of the current download and sends them over the local Native Messaging pipe — never to a remote server.
  • nativeMessaging — to talk to SIDM.BrowserHost.exe, the local bridge process installed alongside the desktop app.
  • webRequest / webNavigation / tabs — to detect HLS / DASH manifests as pages load, so the toolbar badge can show how many video streams are grabbable.
  • contextMenus / notifications / storage — "Download with SIDM" right-click, "Queued / Failed" toasts, and persisting your extension settings locally.

Crash reporting (opt-in)

The desktop app has a disabled-by-default crash reporting toggle in Settings. If you opt in, stack traces are sent to a Sentry DSN you configure; URL / cookie / filename values are scrubbed before sending. No analytics, no clicks, no telemetry beyond the crash payload.

Updates

SIDM checks GitHub Releases on launch (toggleable in Settings → Updates). Only the version manifest and the update package are transferred.
